What audit and testing are

An audit is a review of an existing system: how secure it is, how fast, how well it is written and how much it costs to maintain. The result is a clear list of problems, ordered by importance.

Testing is checking that software does what it should before it reaches users. Both for a new system and for every change to an existing one.

Without checks

  • Vulnerabilities you don’t know about
  • Bugs found by your customers
  • “It works, but nobody knows how”
  • A website that keeps getting slower
  • A vendor you have to take at their word
  • An update that breaks something else

What we check

The scope is agreed based on the system and the risks.

Security

Outdated modules, weak passwords, open ports, user permissions and data protection.

Speed

Load times, heavy queries and places where the system slows down.

Code quality

Structure, readability, duplication and how hard the system is to develop further.

Backups

Whether backups exist, where they are and whether recovery actually works.

Server and hosting

Configuration, updates, monitoring and capacity.

Functional tests

Whether the main processes work correctly from start to finish.

Mobile device testing

How the system looks and works on phones and tablets.

Regression testing

Checking that new changes don’t break existing features, before every release.

Acceptance testing

Checking whether the delivered software matches what was agreed.

What’s the difference between an audit and testing?+

An audit assesses the overall state of the system. Testing checks whether specific functions work correctly, especially after changes.

Will the system stop during the audit?+

No. Checks are done carefully, and riskier tests are agreed in advance or run on a copy.

Do you need access to the code?+

For a full audit, yes. Without the code we can check security from the outside, speed and how the system behaves.

Do you do penetration testing?+

We check for common vulnerabilities. For a full penetration test against a standard, we recommend a specialised firm.

Can you review another vendor’s work?+

Yes. That is one of the most common reasons for an audit.

Will you fix the findings?+

If you wish. We can fix them or help your vendor do it.
